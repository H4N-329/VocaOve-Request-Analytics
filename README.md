# ボカオバリクエスト分析 v3.0

Googleスプレッドシートを閲覧して #ボカオバリクエスト の曲・アーティスト・投稿ユーザー別ランキングと月次投稿分布を表示する、Vercel用Webアプリです。v2.0の構成を維持しているため、**既存のGitHubリポジトリを更新するだけでv3.0を公開できます**。

## v3.0の主な機能

| 改善項目 | 内容 |
|---|---|
| ① ランキング精度 | 全角半角・大文字小文字などの正規化。編集可能な表記ゆれ統合辞書。`投稿URL + 曲名 + アーティスト` が一致する重複行の除外（ON/OFF可）。同一X投稿に別の曲が書かれていれば別のリクエストとしてカウント。 |
| ② ランキング分析 | 全期間・直近30日・直近7日の切替、**直前の同期間**とのランキング順位比較、NEW（履歴にない楽曲）と再登場、期間中の初登場楽曲一覧、CSV出力への順位変動追加。 |
| ④ 自動更新 | サイト訪問時に読み込み、**サイトを開いている間は5分おき**に再取得。タブに戻ったときも必要に応じてチェック。更新時も検索や期間の絞り込みを保持（列構造が変わった場合は初期化されることがあります）。自動更新のON/OFFを切替可能。 |
| ⑤ デザイン・UI | TOP3の強調、ダークUI改良、スマホ対応、Xで共有するボタン、任意のジャケット画像URL列対応（なければ音符の代替画像）。 |

従来の楽曲ランキング・アーティストランキング・月別投稿分布・投稿ユーザーランキング・キーワード検索・日付範囲指定・投稿一覧・Xリンク・CSVエクスポートも引き続き使えます。

## 既存サイトへの反映（推奨）

1. `voca-request-ranking-v3.zip` を解凍します。
2. **ZIP内のファイルを全部**、既存のGitHubリポジトリ直下（現在v2.0の `index.html` がある場所）にアップロードして更新・追加します。ZIPの外側の `voca-request-ranking-v3` フォルダを丸ごと1階層増やさないでください。
3. 変更を `Commit changes` で保存し、Vercelのデプロイが `Ready / Production` になるのを確認します。Git連携済みの `main` ブランチへのコミットでVercelは自動デプロイされます。
4. これまでと同じ公開URLにアクセスし、画面上部の `v3.0` とランキングを確認します。以前の見た目が残る場合は強制リロードを試してください。
5. `集計元データ` の `gid` と「列の設定」を確認します。初回接続時は従来どおりGoogle Sheetsを読み込みます。v2.0から保存された列設定も、同じ列名なら引き継がれます。

以前のGitHubリポジトリは**削除しない**でください。Vercelで新規プロジェクトを作る必要もありません。

### 追加ファイル

- `lib/v3.mjs`: 重複除外、表記ゆれ、日付範囲、順位変動・新着判定。
- `aliases.json`: すべての閲覧者に適用する統合ルール（初期値は空）。
- `tests/v3.test.mjs`: v3機能のテスト。

`api/sheet.js` はv2.0と同じスプレッドシートIDを使用し、キャッシュ期間を短縮したものです。

## 表記ゆれ統合の使い方

サイトの **「✦ 表記ゆれの統合」** を開き、「種類」（楽曲／アーティスト／ユーザー）・「元の表記」・「統一する表記」を指定して登録します。

例：

- 種類 `楽曲` / 元の表記 `星屑エコー(別表記)` / 統一する表記 `星屑エコー`
- 種類 `アーティスト` / 元の表記 `旧名義` / 統一する表記 `現在の名義`
- 種類 `ユーザー` / 元の表記 `@old_id` / 統一する表記 `@new_id`

**重要：画面から登録したルールは、そのブラウザのlocalStorageにのみ保存されます。他の閲覧者のランキングに直接は反映されません。** 全閲覧者に共通で適用する場合は「統合ルールをJSON保存」から `aliases.json` をダウンロードして、GitHubのリポジトリ直下にある同名のファイルを置き換え、コミットしてください。そのコミットのVercel反映後に適用されます。共通ルールとブラウザ固有ルールが重なればブラウザ固有ルールを優先します。

`aliases.json` の例（実際の収録曲やアーティスト名を仮定したデータではありません）：

```json
{
  "songs": { "曲の別表記": "統一する正式な曲名" },
  "artists": { "旧アーティスト名": "統一するアーティスト名" },
  "users": { "@old_handle": "@new_handle" }
}
```

同一楽曲名でもアーティストが異なれば別の曲として集計します。Remix・カバーなど意図的に曲を区別したい場合は、不必要な統合を登録しないでください。

### 重複行の判定

重複判定は `投稿URLの正規化 + 楽曲名 + アーティスト名` の組合せです。X/Twitterの同じステータスIDはURL表記やクエリパラメーターが変わっても同一と扱います。**投稿URLがない行は自動的に重複削除しません。** 視聴者が同じ曲を別々の投稿でリクエストした場合は別件として残します。設定は「表記ゆれの統合」パネル内のチェックで切替できます。

## 期間比較・NEWの定義

- `直近7日`: 日本時間の今日を含む7暦日。前の7暦日と比較。
- `直近30日`: 今日を含む30暦日。前の30暦日と比較。
- `全期間`: すべての記録を集計。期間比較表示はありません。
- `↑ 2`: 前期間より順位が2つ上昇、`↓ 1`: 1つ下降、`→ 同順位`: 同じ順位。
- `NEW`: 現在の期間に登場したが過去の認識できる日付のデータに登場せず、投稿日不明の同一曲もない楽曲。`再登場`: 過去には登場したが、直前期間のランキングにはなかった項目。
- 並び順は各期間の投稿数で降順、同数の場合は日本語のラベル順で決めます。
- 投稿日が欠損・認識できない行は全期間集計には含まれますが、直近7日／30日や月次分布には含まれません。
- 手動で開始日・終了日を指定すると、自動的に `全期間` モードへ切り替わり、入力された日付の範囲で絞り込みます（このとき順位比較は表示しません）。

## Google Sheetsの自動更新

- ページを開くとデータ取得します。
- 自動更新ONのときは、**開いているタブが表示中**の間、最短5分ごとに取得します。画面を閉じている間のバックグラウンド実行や、Google Sheetsが編集された瞬間のPush通知をするものではありません。
- 更新ボタンをクリックすると即時に再取得し、VercelのCDNキャッシュを回避します。
- 通常のリクエストはVercel CDNで60秒キャッシュし、状況によって短時間古い内容を表示する場合があります。新しいリクエストを見たい場合は「データを更新」を押してください。
- リクエスト元シートへの書き込みやXからの自動投稿収集は行いません。

## ジャケット画像

スプレッドシートに追加列 `ジャケットURL`、`画像URL`、`サムネイルURL` などがある場合、列名から自動認識します。`⚙ 列の設定` で手動指定も可能です。**HTTPSの画像URL**がある楽曲にサムネイルを表示します。URLがない曲や取得できない曲は音符のアイコンになります。画像のホスティング・取得は自動では行いません。

## セキュリティ・公開に関する注意

- Google SheetsのCSVを公開取得する方式を維持します。原則として共有設定「リンクを知っている全員 / 閲覧者」が必要です。
- `/api/sheet` からCSVを取得できるため、元シートが公開してよいデータのみを含むことを確認してください。個人情報や非公開データが混ざる場合は、この構成のまま一般公開しないでください。
- X投稿URLやアカウント情報を公開する場合は利用規約・公開条件に注意してください。
- サイトからシートの内容を変更したり、Googleアカウントへログインしたりすることはありません。
- ジャケット画像は外部提供サイトへアクセスする場合があります。画像URLは権利や利用条件を確認して使用してください。

## ファイル構成

```text
index.html           HTML / UI
styles.css           デザイン / レスポンシブ
app.js               画面、操作、自動更新、CSV出力
api/sheet.js         Google Sheets のCSVプロキシ（Vercel Functions）
lib/analytics.mjs    CSV解析、列認識、レコード・ランキング集計
lib/v3.mjs           表記ゆれ、重複除外、期間比較
aliases.json         全閲覧者共通の統合ルール
vercel.json          Vercel設定
package.json         Node.jsテスト・開発コマンド
tests/               集計・API・v3処理の自動テスト
```

### 開発者向け

Node.js 20以上で `npm test` を実行すると単体テストできます。実際にVercel Functionsを含めてローカルで実行する場合は `vercel dev` を使用してください。デモは `?demo=1` で表示でき、Google Sheets接続なしでUIの確認ができます。開発版デモの曲名は架空です。ブラウザでローカル静的サーバーを使用すると `/api/sheet` は動作しません。

元のスプレッドシートIDは従来どおり `api/sheet.js` に固定され、Vercel環境変数 `SHEET_ID` でも上書きできます。
