## v3.8から継続：埋もれたボカロ曲を発掘

- 集計サマリーの直下・楽曲ランキングの上に **「埋もれたボカロ曲を発掘」** セクションを設置。
- **ランダムで最大5曲**（対象が4曲なら4曲、それ未満なら候補数分）を紹介。「↻ もう一度選ぶ」で再抽選。
- 全期間のシートを対象に、曲名＋ボカロPの組合せで楽曲を判別します。同名・別ボカロPは別曲です。
- まずリクエスト**2件以下**の曲を候補にし、5曲に満たない場合は3件以上へ段階的に拡張します。
- その候補から **ボカロPの全楽曲合計リクエスト数が少ないほど選ばれやすい**重み付きランダム抽選を実施します。必ず一番少ないPが選ばれる方式ではありません。
- 可能なら**異なるボカロPを優先**。同じ曲が同一回の5枚に重複表示されることはありません。
- 再抽選時は、まだ表示していない候補を優先します。候補が5曲以下なら同じ曲が出る場合があります。
- 各カードに曲名、ボカロP名、楽曲のリクエスト数、ボカロP全体のリクエスト数を表示します。
- 「投稿を見る」で投稿データ一覧に移動、「動画を探す」で既存のVocaDB動画検索へ、確定済み動画があれば「動画を見る」で直接移動します。
- 7日/30日の絞り込みやキーワード検索の影響を受けず、**全期間**のリクエストから抽選します。ただし既存の表記統合と重複除外設定は反映します。
- スプレッドシート更新後、統合ルール変更後、重複除外の変更後には候補を再計算します。
- 新しいAPIキーやGoogle Sheetsの列追加は必要ありません。ページ側の抽選で、追加通信も発生しません。

**この機能で「少ない」はあくまでスプレッドシートのリクエスト回数です。楽曲全体の再生回数・知名度・人気を示すものではありません。**

## 既存機能：リクエスト登録（v3.7から継続）


- ページ上部「＋ リクエスト登録」をクリックすると、入力フォームが開きます。
- 必須項目：日付、ユーザー名、曲名、ボカロP、X投稿URL。
- 本番用の管理パスワードを追加で入力した場合のみ、APIがGoogle Sheetsの「シート1」に1行追記します。
- 登録時に元データの見出しを確認して誤列への書き込みを防止。同じ **X投稿ID＋曲名＋ボカロP** の組み合わせは二重登録を防ぎます。
- 入力日付は `YYYY/MM/DD`、投稿URLは追跡クエリを除外した `https://x.com/i/status/<投稿ID>` に統一します。
- 登録成功後に最新データを再取得し、ランキングへ再集計を反映します。
- 管理パスワードとGoogleの認証情報はブラウザ内・GitHubに保存しません。
- 既存動画URLのF列は変更しません。

## 【重要】Google Cloud / Vercel での初回設定

Google Sheets APIは公開CSVの読み込みとは異なり、**編集用のGoogle認証**が必要です。

### STEP 1: Google CloudでSheets APIを有効化

1. https://console.cloud.google.com/ を開く。
2. プロジェクトを新規作成（既存プロジェクトでも可）。
3. 左メニュー「APIとサービス → ライブラリ」から「Google Sheets API」を探し、「有効にする」。
4. 「IAMと管理 → サービス アカウント → サービス アカウントを作成」で、例 `voca-request-editor` を作成する。GCPプロジェクト全体の「編集者」ロールは不要。
5. 作成したサービスアカウントの「キー → 鍵を追加 → 新しい鍵を作成 → JSON」でJSONキーをダウンロードする。
6. そのJSON内の `client_email`（例 `voca-request-editor@<project-id>.iam.gserviceaccount.com`）をコピーする。

参考：https://developers.google.com/workspace/guides/create-credentials

### STEP 2: 元のGoogleスプレッドシートへ編集権限を付与

1. https://docs.google.com/spreadsheets/d/10R20NZZYk4FzQ29HN8NcCr7oeSxUcceFKzdMpp9AkUU/edit を開く。
2. 「共有」をクリック。
3. `client_email` のメールアドレスを入力し、権限を **編集者** にして共有する。
4. 「リンクを知っている全員」の権限を編集者に変更する必要はありません。**一般公開の編集権限を付けないでください。**

### STEP 3: Vercelの環境変数に秘密情報を登録

1. Vercel Dashboardの既存プロジェクト `vocaove-request-analytics` を開く。
2. 「Settings → Environment Variables」を開く。
3. 次の値を **Production** の環境に登録する。

| Key | Value | 必須 |
|---|---|---|
| `GOOGLE_SERVICE_ACCOUNT_JSON` | ダウンロードしたJSONキーの**ファイル全体の中身**（`{...}`） | ✓ |
| `REGISTRATION_ADMIN_PASSWORD` | 自分で決めた16文字以上の強い管理パスワード | ✓ |
| `SHEET_ID` | `10R20NZZYk4FzQ29HN8NcCr7oeSxUcceFKzdMpp9AkUU` | 省略可（初期値設定済み） |
| `SHEET_TAB_NAME` | `シート1` | 省略可（初期値設定済み） |

4. 本番用に新しいデプロイを実行する（変数の変更は既存デプロイへは反映されません）。
5. GitHubにこのZIPのソースを反映 → `Commit changes` → Vercel `Ready / Production` を確認する。

> JSONキーや管理パスワードは、GitHubのファイル、README、公開サイトのHTMLやJavaScriptに絶対に書かないでください。このチャットにも送らないでください。必要であれば、Google Cloudのキーをローテーションしてください。

### STEP 4: 動作確認

1. 公開サイト https://vocaove-request-analytics.vercel.app を開く。
2. 上部「＋ リクエスト登録」を押す。
3. 日付／ユーザー名／曲名／ボカロP／X投稿URL／管理パスワードを入力する。
4. 「この内容で登録する」を押す。
5. 正常なら「スプレッドシートに登録しました」と表示されます。元シート末尾に追加されていることとランキングへの反映を確認します。
6. テストで本番シートに登録した行が不要なら、**元シートでその行を手動削除**してください（画面からの取消は未実装）。

## GitHubへの上書きとデータ保護

- ZIPを解凍し、ファイル・フォルダを **既存GitHubリポジトリ直下**に追加または上書きしてください。
- **`aliases.json` と `video-links.json` は既存データ保護のためZIPに含めていません。** GitHubにあるファイルを削除・上書きしないでください。
- 新規ファイルは `api/register.js`、`lib/registration.mjs` などです。`vercel.json` のFunction設定も更新します。
- すべての設定はユーザーのVercel・Google Cloud側で行うため、本ZIPには実際の秘密鍵は含まれていません。

## セキュリティの考え方

- 閲覧は従来どおり公開、**書き込みは管理者パスワード必須**。
- サーバーがパスワードを検証し、Googleサービスアカウントで追記。認証JSONはサーバーの環境変数のみから読みます。
- パスワードはブラウザのlocalStorageには保存しません。HTTPSの同一オリジンPOSTで送信します。
- 日付、文字数、X投稿URL、シートの列順を検証し、Sheets APIの `RAW` 形式で追記します（数式として解釈されない方式）。
- 同時刻の複数登録を完全に防ぐトランザクションロック、IPごとのレート制限、ユーザー単位のログイン認証は未実装です。管理パスワードは少数の信頼できるメンバーだけに共有してください。必要に応じてVercelのレート制限などの追加保護を推奨します。
