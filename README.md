# ボカオバリクエスト・ランキングダッシュボード v2.0

指定のGoogleスプレッドシートで管理している **#ボカオバリクエスト** のリクエストを集計する、Vercel向けのWebアプリです。外部UIライブラリ・有料APIは使用しません。

## 実装した機能

1. **楽曲ランキング**：曲名＋アーティスト名ごとのリクエスト件数ランキング（多い順）。
2. **アーティストランキング**：アーティスト別のリクエスト件数ランキング（多い順）。
3. **投稿分布**：投稿月ごとのリクエスト件数を棒グラフで表示。データが0件の月も表示。
4. **投稿ランキング**：ユーザーごとのリクエスト件数ランキング（多い順）。

追加で、キーワード検索・日付絞り込み・クリックによる投稿一覧への絞り込み・Xの元投稿URLの参照・CSV保存・ランキング全件表示・スマートフォン対応・列名の自動判定と手動設定を実装しています。

> **重要**：今回はユーザーから提供された説明に基づき開発しました。元のGoogleスプレッドシートの実際の表見出しや行内容へのアクセスは確認できていません。実データの列対応と集計結果は公開前に確認してください。`?demo=1` は架空データです。

## Vercelに公開する

1. このZIPを展開し、フォルダの**中身**（`index.html`, `app.js`, `styles.css`, `api/`, `lib/`, `vercel.json`, `package.json` など）をGitHubの新しいリポジトリのルートに置きます。
2. Google Sheetsの「共有」を開き、**リンクを知っている全員 / 閲覧者**に設定します。*公開可能なデータであることを必ず確認してください。*
3. [vercel.com/new](https://vercel.com/new) でGitHubのリポジトリをImportします。Framework Presetは `Other`、Root Directoryはリポジトリルート、ビルドコマンドは不要です。
4. Deploy後のURLを開くと自動でGoogle Sheetsの`gid=0`のCSVを読み込みます。対象タブが異なる場合、シートURL末尾の `#gid=123456789` の数字をページの `シートのgid` 欄に入れて「データを更新」をクリックします。
5. 自動判定で曲名・アーティスト・投稿ユーザー・投稿日・投稿URLが正しく選択されているか**「⚙ 列の設定」**で確認します。正しくない場合は各列のドロップダウンを設定して「この列設定で集計」をクリックします。設定はブラウザに保存されます。
6. Google Sheetsに追記したら、Webの「データを更新」を押して再取得してください（このボタンはキャッシュを回避して取得します）。

既存のVercelプロジェクトを更新する場合は、**元のGitHubリポジトリ内のファイルを今回の内容で置き換え**、Commit/Pushしてください。Git連携済みならVercelへ自動再デプロイされます。

## CSVを使った動作確認

元シートの「ファイル」→「ダウンロード」→「カンマ区切り形式(.csv)」から、対象のタブだけをCSVとして書き出せます。公開済みアプリで「CSVを読み込む」を押してファイルを指定すると、**アップロードせずにブラウザ内で集計**できます（CSV最大5MB）。

サンプルデータはサイトURL末尾に `?demo=1` を付けるか、「サンプル表示」ボタンで表示できます。デモの曲・投稿・ユーザー・URLは架空の例で、シートの実データではありません。

## スプレッドシート列構成

見出しの表記違いをある程度自動判定します。判定できなければ手動選択できます。

| データ | 列名例 |
|---|---|
| 曲名 | 曲名、楽曲名、リクエスト曲、タイトル |
| アーティスト | アーティスト名、ボカロP、作曲者 |
| 投稿ユーザー | ユーザー名、投稿者、アカウント |
| 投稿日 | 投稿日、投稿日時、日付、created_at |
| 投稿URL | 投稿URL、ツイートURL、ポストURL、リンク |

日時は日本時間（Asia/Tokyo）を基準に集計。対応する日付例：`2026/11/01`、`2026-11-01 13:00`、`2026年11月1日`、`2026-10-31T16:30:00Z`、Google Sheetsの日付シリアル値。日時が判定できない行は月次グラフから除外されますが、投稿日が必須でないランキングには含まれます。

## 集計ルール

- **1行＝1リクエスト**としてカウント。同じURLや楽曲が重複して記入されている場合は、別の行として計上します（勝手に重複を削除しません）。
- 楽曲は `曲名＋アーティスト` の組み合わせで分類。同じ曲名でもアーティストが違えば別の曲とします。
- 表記ゆれは、全角・半角、英字の大文字・小文字、前後と連続する空白を自動統一します。リミックス違い、別名義、表記揺れが大きいものは自動で合算しません。
- アーティスト列に複数人が一緒に書かれている場合は、その**セル全体をひとつのアーティスト表記**として集計します。
- 月次グラフは最初の投稿日から最後の投稿日までを表示します。月別件数はCSV出力または「月別件数の表を表示」で確認できます。
- 同数の場合は日本語ロケールで名前順に並べます。
- 各ランキングをクリックするとその楽曲／アーティスト／投稿者のデータに絞り込まれ、下部の投稿一覧から元のXの投稿へ移動できます。
- 各ランキング、月別投稿数、投稿一覧をCSVで出力できます。

## 構成と安全性

```text
index.html          画面
styles.css          レスポンシブデザイン
app.js              読込／描画／フィルタ／CSV保存
lib/analytics.mjs   CSV解析／列名推定／集計処理
api/sheet.js        Google Sheets CSV取得用 Vercel Function
vercel.json         Vercel Other preset
package.json        npm test / npm run dev
tests/              集計ロジックの単体テスト
```

`/api/sheet` は**一般に閲覧可能なGoogle Sheets**からデータを読み出す設計で、アクセスする人ならAPIを通じてシート全体のCSVを取得できます。個人情報や非公開データが混ざる場合は、この構成のまま公開せず、Google Sheets APIサービスアカウント＋認証／最小限の列だけを公開するAPIに変更してください。

**注意**：Xの投稿ユーザー名・ポストURLなどを公開する場合、公開可否や各種規約を確認してください。Google SheetsやXの内容をVercelに書き戻したり、投稿を自動収集したりする機能はありません。

## ローカルで確認

- Node.jsのある環境で `npm test` を実行すると集計ロジックのテストを行えます。
- Vercel CLIインストール済み環境で `vercel dev` から実際の Google Sheets API プロキシも含めて動作確認できます。
- 静的画面とデモだけ試す場合は、このディレクトリで `python3 -m http.server 8000` して `http://localhost:8000/?demo=1` を開きます。`/api/sheet` は静的サーバーでは動作しません。

元シートを変更したい場合はVercelの環境変数に `SHEET_ID` を登録してシートIDを指定し、再デプロイしてください。
